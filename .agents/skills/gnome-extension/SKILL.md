# GNOME Shell extension

Owning files: `gnome-shell/screenpad-touchbar@screenpad/` — `extension.js` (draws the bar, the strut, drops, `Launch`, `renderer.json`), `tiles.js` (one tile's actors: the grip, an icon, an app's icon, text), `pages.js` (below the bar: the touchpad page's black screensaver, its clock and battery level, the apps page's surface and its widgets), `notifications.js` (mirrors notifications to the daemon), `safeguard.js` (the repaint safeguard: a transparent full-monitor actor, the stage's `after-paint`, logind's `PrepareForSleep`, one timer), `keepout.js` (keeping the desktop off the ScreenPad: pointer barriers, moving windows back, the overview's ScreenPad view hidden), `osd.js` (Fn+F6's ScreenPad on indicator, wrapping GNOME's `OsdWindowManager`), `custom.js` (the picker's custom shortcut window, a `ModalDialog` on the main screen), and the plain modules they import: `contract.js` (what the extension and the daemon agree on: file names, the handshake, the D-Bus interface, the chrome options, `GROW_MS`), `scene.js` (which scenes are drawn, the layout key, where tiles, text, badges and the grip go, drops, launches, what the pages show and their sizes, the battery level's text), `widgets.js` (the apps page's widgets: which are drawn, the rebuild key, each one's box, type and fixed-width lines), `cards.js` (the `hello`, `notify` and `cancel` messages, answers and which button one presses), `feedback.js` (when the press click plays), `repaint.js` (when the safeguard repaints the whole ScreenPad monitor), `fence.js` (where the barriers go, which windows go back to the primary monitor and where), `fnkey.js` (when ScreenPad on shows, and which of GNOME's indicators it replaces) and `shortcut.js` (what a key press records in the custom shortcut window, and the `shortcut add-key` or `add-command` arguments it runs); `click.wav` (the click, written by `gnome-shell/make_click.py`, which sits outside the folder so it is not installed), `stylesheet.css`, `metadata.json`. `install.sh` copies every file in that folder to `/usr/local/share/gnome-shell/extensions/screenpad-touchbar@screenpad/`, so keep only extension files there.

## Rules

- **GNOME Shell 50, ES modules** (`gi://` and `resource:///org/gnome/shell/...` imports). `metadata.json` declares `"shell-version": ["50"]`; supporting another version means checking the APIs used there.
- **Logic goes in the plain modules, GNOME in the others**: `contract.js`, `scene.js`, `widgets.js`, `cards.js`, `feedback.js`, `repaint.js`, `fence.js`, `fnkey.js` and `shortcut.js` import nothing but each other (no `gi://`, no `resource://`, no Node or GJS API beyond `TextEncoder`), so the tests run them under node. Put a decision or a computation there, as a function of plain values, and keep in `extension.js`, `tiles.js`, `pages.js`, `notifications.js`, `safeguard.js`, `keepout.js`, `osd.js` and `custom.js` only what needs GNOME Shell: actors, files, D-Bus, drag and drop, the socket.
- **The extension draws tiles without knowing what they are**: it reads the scene from `$XDG_RUNTIME_DIR/screenpad/touchbar.json` and draws each tile's icon, app icon, text or grip with its classes (`tileContent`). No tile kinds and no version 1 spots: ESLint refuses any `.kind` or `.spots` (`no-restricted-properties` in `eslint.config.js`); new behavior goes in the daemon.
- **The pages come from the scene** (`pagesFrom`): the screensaver goes in `global.window_group` just above `Main.layoutManager._backgroundGroup`, so windows stay over it; the apps surface is chrome (`BAR_CHROME`) kept under the bar, over windows, and reactive so a mouse click does not fall through. Both cover only the ScreenPad's monitor and exist only while the bar is drawn. Black is drawn; the extension never touches brightness, and the clock redraws once a minute. The battery level is not in the scene: `pages.js` reads UPower's display device (the shell's own `org.freedesktop.UPower.Device` interface, as its power indicator does, never sysfs), and `batteryText` decides what shows; the label changes only when that text does, and has no setting.
- **The apps page's widgets are drawn like tiles** (`surfaceWidgets`): a rectangle in panel pixels and what to draw (an `app`, a desktop file id, is that app's icon when it has no `icon`), nothing about what they do; the daemon decides every touch. `Launch` opens only an app the scene shows, as a tile or a widget (`canLaunch`). A press restyles (`widgetsKey` leaves out `pressed`); a widget's `lines` are one fixed-width label shrunk to fit (`LINE_HEIGHT`). A scene without `widgets` (an older daemon, or the renderer below its protocol) draws the page's title, text and hint as before.
- **Narrow tiles (a `glyph`: the grip, drawn by its own code, and the page button, drawn from its icon) do not limit the icon size** (`barGeometry`), so a narrow tile never shrinks the others' icons; `iconSizeFor` fits an icon to its own tile. An unknown glyph with an icon draws as an icon tile, which is how an older extension draws the page button.
- **The repaint safeguard damages the whole ScreenPad monitor for two frames** (mutter's damage-only copy into two NVIDIA buffers; [docs/touchbar.md](../../../docs/touchbar.md#the-repaint-safeguard)): by queuing a redraw on its own empty, non-reactive actor over exactly that monitor, never by drawing anything. Keep it bounded: its own frames are not activity, the settle repaint is once per burst (`SETTLE_MS`, `MAX_WAIT_MS`), one timer re-armed only to fire earlier, and only while the bar is drawn. When and how often is `repaint.js`; change it there, with its tests.
- **The desktop is kept off the ScreenPad** ([docs/touchbar.md](../../../docs/touchbar.md#keeping-the-desktop-off-the-screenpad)) whenever the scene names a monitor GNOME has, not only while the bar is drawn, and never when it is the primary. Events only, no timer, no setting written (not `workspaces-only-on-primary`, not the display settings). Barrier lines go on the other monitor's pixels (mutter stops the pointer on the line itself) and let the pointer leave; they come down during the overview's `item-drag-begin`/`-end` so apps still drop on the bar. Windows move in one `BEFORE_REDRAW` later, never inside mutter's signal, and not while grabbed. The overview's ScreenPad view is hidden through an `InjectionManager` override of `WorkspacesDisplay._updateWorkspacesViews`, restored in `destroy()`. Decisions go in `fence.js`, with its tests.
- **Fn+F6's ScreenPad on indicator** ([docs/touchbar.md](../../../docs/touchbar.md#fnf6-touchpad-and-display)) follows the scene's `fnkey` (`lit` rising in the same `pid`, `lights_next`): `osd.js` wraps `OsdWindowManager.prototype.showAll` and `showOne` through an `InjectionManager`, restored in `destroy()`, and replaces only GNOME's `touchpad-disabled-symbolic` indicator of the press that lights the display, once, whichever comes first (`SAME_PRESS_MS`); every other indicator passes, and a failure deciding shows GNOME's. It shows on the primary monitor. No timer: only scenes and GNOME's indicators drive it. Decisions go in `fnkey.js`, with its tests.
- **A tile's `text_rows` caps its text size** (`textLines`): its title and text are sized at most as on a bar that many panel rows tall (`barGeometry`'s `sy`), and wrap is decided from the capped sizes. The daemon sets it on a card's text and answers (the default bar height), so a tall bar's card keeps the default card's type and wraps; other tiles, and every icon, are sized as before.
- **A press restyles, it does not rebuild**: the layout key (`layoutKey`) leaves out `pressed`, so a finger going down or up only changes a tile's style.
- **What is mirrored from the daemon (`screenpad_touchbar/common.py`) must match**: in `contract.js` `STATE_NAME`, `RENDERER_NAME`, `RENDERER_PROTOCOL`, `SOCKET_NAME`, `DBUS_PATH` and the `DBUS_XML` interface, `CLI_FALLBACK` (`install.sh`'s `TOUCHBAR`); in `cards.js` `APP`, `URGENCY`, `ACTION` and the `notify` message fields. `GROW_MS` stays below the daemon's `ASK_ARM` so a card is fully drawn before it takes a tap. The tests check each one, and feed what the modules build to the daemon's own code.
- **`renderer.json` tells the daemon whether the bar is on screen**: written while enabled (`{protocol, drawn}`), removed in `disable()` before the bar is destroyed. The daemon shows questions only while it says drawn.
- **`addChrome` takes only `trackFullscreen` and `affectsStruts`** in GNOME 50, so `extension.js` and `pages.js` pass only `BAR_CHROME` or `STRUT_CHROME` from `contract.js`: any other key throws after the actor is already on stage, and the shell then drops the stylesheet. The strut is the bar's own height; a card's extra height covers windows instead of resizing them.
- **The custom shortcut window** opens only when the daemon calls `AddItem(place)` (`"bar"` or `"apps"`, refused otherwise), which it does only at `CUSTOM_PROTOCOL`; it decides nothing about the config: Add runs `screenpad-touchbar shortcut add-key` (evdev key codes, Clutter's hardware code less 8, which the daemon names) or `add-command` (`addArgs` in `shortcut.js`), and shows the command's error. One window at a time, destroyed in `disable()`.
- **The press click follows the daemon's count**: the extension plays `click.wav` through `global.display.get_sound_player()` (`play_from_file`, so GNOME's event-sounds switch and volume apply) only when the scene's `clicks` rises in the same daemon (`pid`) (`Clicker`, `clicked`); it decides nothing about which touches click, the daemon does. No setting: event sounds turn it off. Keep the sound short and soft (the tests check 10 to 30 ms, under 0.35 of full scale), and change it only in `make_click.py`, then rerun it.
- **Only notifications' own buttons are pressed**, and only when that notification and that button still exist (`actionToPress`); dismiss, timeout or the bar going away only close the card.
- Every `style` and class a tile can carry has a rule in `stylesheet.css`; CSS class names outside `CLASS_NAME` are dropped.
- Formatting is Prettier (`.prettierrc.json`: 4 spaces, single quotes, no bracket spacing) and lint is ESLint (`eslint.config.js`, with the GJS globals); `make format-check lint` checks both. Then run `make test`, which runs the plain modules.

## Tests

- `tests/test_touchbar_extension.py` runs `contract.js` and `scene.js` under node (`js()` in `tests/touchbar_support.py`): the names against the daemon's, the `DBUS_XML` interface, `rendererJson` read by the daemon's `renderer_ready`, and `scene.js` on scenes the daemon publishes (the layout key, launches, classes and content, every tile, the grip and the page button drawn at every height, the pages (`pagesFrom`, the clock's minute, `batteryText`), a card's growth, text and its size capped on a taller bar (`text_rows`), the divider and badges, drops given to the real `shortcut add`). It also checks the stylesheet has a rule for every style and class.
- `tests/test_touchbar_extension_widgets.py` runs `widgets.js` on the apps page the daemon publishes: malformed widgets dropped, a press not rebuilding, every widget and its type fitting at two scales; and the stylesheet's rule for every widget class (`WIDGET_CLASSES`).
- `tests/test_touchbar_clicks.py` runs `feedback.js` with a stand-in sound player on the scenes the daemon publishes, and checks `click.wav` is what `make_click.py` writes.
- `tests/test_touchbar_extension_repaint.py` runs `repaint.js` with a stand-in clock, a simulated timer and stage: two frames per repaint, the settle repaint once per burst and at most `MAX_WAIT_MS` apart, no loop on its own frames, display events, no timer while idle, giving up without frames, and the timer re-armed only to fire earlier.
- `tests/test_touchbar_extension_keepout.py` runs `fence.js`: the barriers on each side and on the shared part only, one per neighbour, their directions Meta's names, none to put up, which windows go back, where a hanging one goes, and the one overview view hidden. `keepout.js` itself is checked in a headless GNOME Shell ([docs/development.md](../../../docs/development.md#tests)).
- `tests/test_touchbar_extension_fnkey.py` runs `fnkey.js` on the scenes the daemon publishes round Fn+F6's cycle: ScreenPad on shown and GNOME's touchpad-off replaced in both orders, once, not too late, nothing for other indicators, a restarted, stopped or older daemon. `osd.js` itself is checked in a headless GNOME Shell with GNOME's `ShowOSD`.
- `tests/test_touchbar_extension_cards.py` runs `cards.js`: its messages through the daemon's `parse_notify`, apps and bar, and the daemon's answers back through `parseAnswer` and `actionToPress`.
- `tests/test_touchbar_extension_shortcut.py` runs `shortcut.js`: a key press while recording, what the button shows, what is missing, and its arguments run by the real command line.
- Only names that cross into GNOME Shell are read from the source: that `extension.js` defines `Launch` and `AddItem` and passes only `BAR_CHROME` or `STRUT_CHROME` to `addChrome`. Add no other source check: move the logic into a plain module and test it there.
- The tests need node; without it they are skipped, except under CI (`CI` set), where they fail. Nothing runs `extension.js` itself in CI. Check a visible change in a headless GNOME Shell 50 under `dbus-run-session` with its own `HOME` and `XDG_*` directories, **set before `dbus-run-session` starts** (else the services it starts on demand, dconf first, write to your real settings; see [docs/development.md](../../../docs/development.md#tests)), never by reloading the extension in your own session, and refresh the screenshots in `docs/images/` when the bar's look changes.
