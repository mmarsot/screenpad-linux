# Touch bar daemon

Owning files: `screenpad_touchbar/`, one module per concern, and `touchbar.py`, the launcher that runs its `cli.main()`. Installed as `/usr/local/lib/screenpad/`, with `/usr/local/bin/screenpad-touchbar` a link to `touchbar.py` there (see the [install](../install/SKILL.md) skill). The module map is in [docs/development.md](../../../docs/development.md#layout): `common` (constants, errors, runtime files), `codes`, `keys`, `config`, `defaults`, `config_edit`, `scene`, `splitter`, `bar`, `pager`, `protocol`, `widgets`, `notify`, `asks`, `surface`, `apps`, `devices`, `daemon`, `cli`. New code goes in the module of its concern; a module nearing 500 lines is split, not grown.

Read first:

- [docs/touchbar.md](../../../docs/touchbar.md): how the split, the bar, attention cards, notifications and the two pages behave.
- [docs/configuration.md](../../../docs/configuration.md): every `touchbar.toml` setting.
- [docs/app-api.md](../../../docs/app-api.md): the socket protocol for apps and questions.
- The renderer side: the [gnome-extension](../gnome-extension/SKILL.md) skill.

## Rules

- **Standard library only, run isolated.** The shebang is `#!/usr/bin/python3 -I`: isolated mode puts neither the script's directory nor the user's site-packages on `sys.path`, so `touchbar.py` adds the directory it really lives in (through the link) and imports only `screenpad_touchbar` from there. The package's modules use relative imports, and the imports go one way: `common` and `codes` import nothing of the package, `cli` is on top; an import cycle is a bug. A new module is picked up by `install.sh` (it copies the whole package).
- **A contact keeps the kind it started with** (`Splitter`): `Daemon._zone()` decides it once, when the contact starts, from the bar's height and the page: `BAR` above the bar, else `PAD` on the touchpad page and `SURFACE` on the apps page. A touch that starts in the bar never reaches the virtual touchpad, a touchpad touch that slides into the bar stays a touchpad touch, and a height change (the grip, an attention card) or a page turn applies only to new contacts. Only `PAD` contacts reach the virtual touchpad. It gets whole frames ending in `SYN_REPORT`; resync after `SYN_DROPPED`.
- **The pages** (`pager.py`): the swipe along the bar (`SWIPE_MIN`, `SWIPE_SLOPE`, `SWIPE_TIME` in `common.py`, one finger, on the bar only) and a tap on the page dots turn them; `Pager.watch()` turns a swipe's lift into a `cancel` before the bar sees it. The apps page shows only while `Pager.available()` (grabbed, and the renderer at `PAGES_PROTOCOL`; the pages and the black are always on, `[screensaver] clock` and `[pager] return_after` are the only settings), and goes back to the touchpad after `return_after` seconds without a contact down, or at once when it can no longer show. Swipes with three or more fingers stay GNOME's, so the pager never claims them. The screensaver is drawn black by the extension; nothing here writes brightness.
- **The apps page** (`surface.py`, pages validated in `widgets.py`): the home page lists apps' pages, an app's page is a grid below the header under the bar's own height (`top`), and a card covers its top. The daemon does the hit-testing and sends `down`, then `tap`, `long` or `cancel` (`Apps.press`, to the page's owner even after it withdrew the page). Two safety rules: a touch that starts within `ASK_ARM` of a widget appearing, changing, moving, the page turning to or a card growing or going does nothing (`Surface.since`, keyed by `Spot.key()`); and a widget that changes or goes under a finger cancels that press. Widgets show and take touches only at `WIDGETS_PROTOCOL`; below it the page shows only its text.
- **The click counts accepted presses only** (`clicks` in the scene, `Daemon._click`, the `click` callback of `Bar` and `Surface`): when the action happens, so a hold button on its touch, and on the lift that fires it for a tap button, an app's tile (`up` inside), a shortcut, the dots, an answer or Dismiss, and a widget's `tap` or `long`. Never a slide away, a cancel, a swipe, the grip or the touchpad. The count lives on the daemon, so a new `Bar` keeps it; it only goes up.
- **The page dots spot is last in `Config.spots`**, after the grip, so the other spots keep the indexes an extension from before tiles knows them by, and it is left out of the version 1 `spots`.
- **The daemon grabs only while `/run/screenpad/active` exists** (`screenpad on`), and only between touches; letting go releases every bar and pad contact first.
- **The config is strict**: unknown keys, settings and bad values are `ConfigError`, and the daemon then keeps the current bar. A new setting needs parsing, its errors, a line in `EXAMPLE_CONFIG`'s comments and in [docs/configuration.md](../../../docs/configuration.md), and tests.
- **The bar edits the config only in place**: `edit_config` rewrites the `height` line and the `[[shortcut]]` blocks and keeps every other line and comment, and refuses an edit that would change anything else.
- **Changing the default config (`EXAMPLE_CONFIG`) needs a migration**: add the sha256 of the default being replaced to `OLD_DEFAULTS`, save that default as `tests/touchbar-v<N>-default.toml`, and add a migration test. A default block that changed goes in `OLD_BLOCKS` (old text, new text), so an edited config gets the new block and keeps the rest. Users' configs are never otherwise rewritten.
- **The scene is drawn without knowing tile kinds**: `touchbar.json` (`SCENE_VERSION`) is a list of tiles with geometry, what to draw, CSS classes and `pressed`. A new kind of tile is daemon-only work, but every `style` and class it uses needs a rule in the extension's `stylesheet.css` (tested).
- **The renderer handshake must match the extension**: `RENDERER_NAME`, `RENDERER_PROTOCOL`, `SOCKET_NAME`, the D-Bus `Launch` interface (all in `common.py`), the notify fields, urgency names, action ids and the notifications app name are mirrored in the extension's `contract.js` and `cards.js`. Bump `RENDERER_PROTOCOL` on both sides when an older extension would misdraw the scene, and gate the new feature on that protocol (as `ASKS_PROTOCOL`, `PAGES_PROTOCOL` and `WIDGETS_PROTOCOL` do), so what an older extension can draw keeps working.
- **Questions show only while they can be seen**: an ask is shown only while the touchpad is grabbed and `renderer.json` says the bar is drawn; otherwise the asker gets `unavailable`. A touch that starts within `ASK_ARM` (0.3 s) of a card growing does nothing, and the extension's growth animation is shorter than that.
- **A protocol change updates [docs/app-api.md](../../../docs/app-api.md)** and the app tests: ops, fields, limits (`MAX_APPS`, `MAX_LINE`, `MAX_OPTIONS`, `MAX_PAGES`, the home page's `HOME_COLUMNS * HOME_ROWS` pages in all, `MAX_WIDGETS`, the grid, timeouts), events and answer reasons.
- Notifications only mirror; a card's button presses the notification's own button and nothing else activates a notification. The mirror rules are `mirror_refusal` in `notify.py`.

## Tests

- One file per area, sharing `tests/touchbar_support.py` (the checkout on `sys.path`, axes, events, `Split`, `ConfigHome`, `FakeClient`, `Conn`, the bar, notify and page fixtures): `test_touchbar_config.py` (keys, parsing, writing, migration), `test_touchbar_bar.py` (the split, the bar), `test_touchbar_scene.py` (tiles, questions and app tiles in the bar), `test_touchbar_apps.py` (apps, the socket, the daemon), `test_touchbar_cards.py` (attention cards), `test_touchbar_clicks.py` (which presses click, and the extension playing it), `test_touchbar_notify.py` (notifications), `test_touchbar_pager.py` (the pages: swipes, dots, routing by page, the return, their settings), `test_touchbar_surface.py` (apps' pages and widgets: validation, the home list, taps, long presses, arming, cancels, routing), `test_touchbar_commands.py` (`shortcut`, `status`, device discovery, the monitor), `test_touchbar_extension.py` (the extension against the daemon's constants), `test_touchbar_extension_widgets.py` (`widgets.js` on the apps page the daemon publishes). A new test goes in the file of its area.
- They run with no root, no hardware and no uinput: events are fed as tuples, `ConfigHome` points `XDG_CONFIG_HOME` and `XDG_RUNTIME_DIR` at a temporary directory for the config, the state files and the socket.
- [docs/development.md](../../../docs/development.md#tests) lists what the touch bar tests cover; keep it in step.
